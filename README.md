# 泉师智辅

面向泉州师范学院东海校区教师与辅导员的校园事务智能体平台。项目把学生档案、学生诉求、事项流程、知识库、统计总结和 AI 助手放进同一个角色化工作台。

## 当前能力

- 工作台：学生诉求与迎新数据概览、自然语言批量创建待办、日程和重点学生跟进
- 辅导员数字人：学生使用教师创建的账号登录，每人每天最多20轮；询问类先依据已导入的学校文件回答，学生确认“未解决”后才登记留言，请假、申请、反馈等留言类内容直接原样登记
- 学生诉求中心：留言按学生账号自动投递给所属教师，列表与侧栏角标自动刷新；集中保留数字人对话和学生原话，支持系统回复、登记微信回复、删除记录以及审批对话额度重新计数申请
- 迎新管理：发布新生准备清单、查看两个试点班的个人与总体完成进度
- 学生工作全景：10 类东海校区辅导员高频工作面及学期工作节奏
- 学生档案：筛选、搜索、状态标签和学生详情页，支持从表格、文档和图片批量识别学生并自动归档，也可删除导入的学生
- 事项流程：请假、外宿、资助、心理转介、就业等流程跟踪
- 智能助手：可调用学生诉求汇总、学生档案、知识检索、上传资料检索、待办日程、事项流程、材料生成、工作概览和资料导入九项工具，并返回结果卡片与需确认的执行动作
- 模型设置：用“选平台—填 Key—选模型”三步连接智谱或 DeepSeek；测试通过后全站立即切换，原始 Key 不返回前端
- 智能资料导入：一次最多选择30个文件；表格支持 Excel、CSV、TSV、JSON，覆盖9类辅导员业务数据；非结构化资料支持 DOCX、PDF、PPTX、TXT、Markdown、HTML、RTF、EML、XML 与常见图片。学生名单即使来自文档或截图，也会拆成个人记录进入学生档案；制度与其他材料进入助手资料库，并支持按导入任务删除及同步撤销数据
- 知识库：上传时智能建议“普遍通用”或“教师专用”，老师确认后进入 Qdrant 向量检索；通用资料可供所有教师和学生问答，专用资料只供上传教师检索，原件始终保存在上传电脑
- 统计总结：月报、走访、资助、就业等工作数据汇总
- 数据层：Cloudflare D1 保存结构化记录和资料检索文本，Qdrant 保存分段向量索引，教师上传的原文件保存在当前电脑的浏览器本地文件库，Drizzle 管理迁移

当前纳入的主干工作包括：思想引领与班团、迎新军训、学风考勤与学业预警、奖助评优、心理健康、就业升学、四个100%、日常事务与家校沟通、毕业离校、国防征兵。宿管负责的社区与公寓模块不纳入本平台。

## 本地运行

环境要求：Node.js `>=22.13.0`，推荐使用 pnpm。

```bash
pnpm install
docker compose -f docker-compose.vector.yml up -d
pnpm run dev
pnpm test
```

本地 Qdrant 仅监听 `127.0.0.1:6333`，索引数据写入 Docker 持久卷。复制 `.env.example` 中的 `QDRANT_URL` 配置即可启用向量检索；未配置或向量库临时不可用时，系统自动回退到 D1 关键词检索，上传与问答不会中断。部署到阿里云时同样运行该 Compose 文件，并让应用通过内网访问 Qdrant，不需要额外购买云向量数据库。

首次启动新数据库前，还需要在本地环境文件中设置 `ADMIN_INITIAL_PASSWORD`。系统只在管理员账号尚不存在时使用该值创建 `axbgs`，不会把真实密码写入源码或提交到 GitHub。

智能助手在未配置模型密钥时仍能使用本地业务工具，并可读取有文字层的 Word、PDF、PPT 和文本资料。扫描版 PDF、聊天截图与照片需要视觉模型。普通用户直接打开 `/settings`，选择智谱或 DeepSeek、填写对应 API Key，再选择模型并点击“保存并启用”即可；老师助手、学生端数字人和资料识别会共同使用当前模型。

`.env.local` 仍可作为首次启动或配置页尚未保存时的后备设置。当前本地后备配置使用智谱兼容接口和 `glm-5.3-flash`；密钥文件已被 Git 忽略。通过设置页保存后，当前平台与模型记录在 D1 的 `ai_provider_settings` 表中。

开发地址默认为 `http://localhost:3001`。老师工作台入口为 `/`，学生端入口为 `/student`。项目不内置演示教师或学生账号，教师与学生账号均由管理员或教师实际创建。数据库结构修改后运行：

```bash
pnpm run db:generate
```

## 项目结构

- `app/`：页面、交互组件和 API 路由
- `db/schema.ts`：D1 数据模型
- `drizzle/`：数据库迁移
- `tests/`：服务端渲染冒烟测试
- `.openai/hosting.json`：Sites 运行时资源声明

## GitHub 调研参考

开发前调研了两个方向的开源项目：

- [TPT School](https://github.com/tpt-solutions/tpt-school)：MIT 许可的学校管理系统，参考了角色化导航、学生档案、出勤和事项管理的产品分区。
- [ClassroomLM](https://github.com/TechAtNYU/ClassroomLM)：面向教学组织知识的 RAG 助手，参考了“知识源—问答—行动”的交互思路。
- [Vercel AI SDK](https://github.com/vercel/ai)：采用其类型化工具调用模式，为模型提供统一的校园业务能力。
- [assistant-ui](https://github.com/assistant-ui/assistant-ui)：参考结果卡片、工具状态和建议追问的交互方式，保留现有界面而未整体替换组件库。
- [OpenAI Agents JS](https://github.com/openai/openai-agents-js)：参考人工确认模式，所有写入、发送和发起流程动作都先交由老师确认。

本项目没有直接套用其业务代码；中小学成绩、收费、家长门户等结构不适合高校辅导员场景，因此按东海校区的学生工作流程重新实现。

## 后续接入边界

当前仓库可独立运行。正式部署到校内环境时，可继续接入统一身份认证、教务/学工数据、短信或企业微信、真实大模型服务；相关入口已被拆分为页面与 API 边界，便于替换。

## 开发取舍

- 以东海校区辅导员日常高频、明确、可落地的工作为主，不为极小概率事件增加独立模块、复杂分支或额外流程。
- 安全建设采用够用原则：保留基础登录、角色权限、必要的操作记录和数据备份，不追加复杂加密体系、多层审批、异常风控或高成本安全加固。
- 当功能完整度、操作效率与低概率风险防护发生冲突时，优先保证辅导员能顺畅完成日常工作。
